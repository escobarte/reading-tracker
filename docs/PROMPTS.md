# PROMPTS — Reading Tracker

> Готовые промпты для Claude Code по фазам. Штаб не переписывает промпты, которые уже здесь есть, а ссылается на них.
> Промпт копируется целиком в Claude Code, запущенный в корне репозитория.
> Перед запуском: папка `docs/` с `STATE.md`, `PLAN.md`, `DESIGN.md`, `PROMPTS.md` лежит в репозитории.

---

## Инструкция проекта Claude.ai («штаб»)

Вставить в инструкции проекта «Tracker Reading Book»:

```
Это проект READING TRACKER — личное PWA-приложение для учёта чтения
книг (замена моей базы в Notion). Актуальное состояние всегда в файле
docs/STATE.md (в файлах проекта) — прочитай его в начале каждого чата
и опирайся на раздел «ЧТО ДАЛЬШЕ».

Твоя роль — штаб: планирование, разбор багов, промпты для Claude Code,
продуктовые решения, макеты. Код пишет Claude Code в терминале, не ты.

В начале нового чата: прочитай docs/STATE.md, коротко назови текущий шаг
и спроси, продолжаем ли с него. Если нужны свежие CHANGELOG.md / PLAN.md
для сверки — попроси приложить. Не переписывай промпты, которые уже
лежат в docs/PROMPTS.md, — ссылайся на них. Внешний вид — только по
docs/DESIGN.md.

Ключевые принципы продукта: приложение только ведёт учёт, ридера нет;
mobile-first, Android, одной рукой; только онлайн; светлая тема по
умолчанию; стиль лёгкий стичпанк; ввод прогресса в пару касаний;
одна запись на книгу и отдельный журнал сессий; данные о книге
подтягиваются из Google Books с ручной правкой.

Соблюдай жёсткие правила из docs/STATE.md (git только владелец;
ритуал завершения; дизайн по токенам). В конце сессии, при закрытии
фазы, напомни обновить docs/STATE.md и CHANGELOG.md. В начале каждого
нового добавления (фаза, функция, исправление) предлагай имя ветки по
правилу из docs/STATE.md. Макеты экранов открывай по ссылке из STATE.md.
```

## Фаза 1 — Каркас

```
Ты работаешь над проектом READING TRACKER — личное PWA-приложение для
учёта чтения книг. Прочитай по порядку: docs/STATE.md (особенно «ЖЁСТКИЕ
ПРАВИЛА»), docs/PLAN.md (Фаза 1) и docs/DESIGN.md. Внешний вид, цвета,
шрифты и размеры бери только из docs/DESIGN.md. Композицию экранов
сверяй с картинками в docs/mockups/ (для Фазы 1: home-light.png и
home-dark.png). В самом начале ответа предложи имя ветки по правилу из
STATE.md (для этой фазы подойдёт phase-1/skeleton) и продолжай работу:
ветку создаст владелец.

ЗАДАЧА: Фаза 1 — каркас приложения. Без базы данных, без входа, без
реальных данных. Только оболочка, дизайн-система и заглушки экранов.

1. ПРОЕКТ
- Next.js (App Router) + TypeScript + Tailwind CSS. Менеджер пакетов npm.
- Структура: src/app, src/components/ui, src/components/layout,
  src/lib, src/i18n, public.
- Не добавляй UI-библиотеки (shadcn, MUI и т.п.) и другие зависимости без
  нужды. Для локализации можно next-intl или собственный лёгкий вариант
  (словари + контекст), выбери проще и опиши выбор в отчёте.
- Создай в корне репозитория короткий CLAUDE.md: «Перед работой читай
  docs/STATE.md и docs/DESIGN.md. Git делает только владелец. Дизайн только
  по токенам. Ключи API только на сервере. Не придумывай UI вне DESIGN.md. В начале нового добавления предлагай имя ветки (правило в STATE.md).»

2. ТОКЕНЫ И ТЕМЫ
- Все токены из DESIGN.md, раздел 2, как CSS-переменные в globals.css для
  data-theme="light" (по умолчанию) и data-theme="dark".
- Подключи токены в Tailwind (цвета, радиусы, шрифты), чтобы в компонентах
  не было hex-значений.
- Тема сохраняется (cookie или localStorage) и применяется до отрисовки,
  без вспышки неверной темы.
- Фон приложения с «плетением» из DESIGN.md, раздел 4.
- Шрифты Spectral и IBM Plex Mono через next/font, подмножества latin и
  cyrillic.

3. ЛОКАЛИЗАЦИЯ
- Языки ru (по умолчанию) и en, переключатель на экране настроек.
- Весь текст интерфейса только из словарей. Хардкод строк в компонентах
  запрещён.

4. PWA
- manifest (name, short_name, display: standalone, start_url, theme_color и
  background_color из токенов светлой темы, иконки 192 и 512 и maskable).
- Минимальный service worker, чтобы приложение устанавливалось на Android
  (никакого офлайн-кеша данных, приложение работает только онлайн).
- Временные иконки: сгенерируй простой скриптом (круг цвета --accent с
  белым треугольником «старт» на фоне --bg). Название приложения временно
  «Reading Tracker».
- Мета для мобильного: viewport-fit=cover, theme-color.

5. ОБОЛОЧКА (src/components/layout)
- AppShell: mobile-first, высота 100dvh, на ПК колонка до 480 px по центру,
  safe-area сверху и снизу, контент прокручивается, нижняя навигация
  закреплена.
- BottomNav строго по DESIGN.md («BottomNav»): Главная, Книги, Старт
  (приподнятая круглая кнопка), Заметки, Статистика. Активный пункт
  подсвечивается. Маршруты: / , /library , /session , /notes , /stats .
- PageHeader (метка «Reading Tracker» + заголовок экрана + место для
  кнопок справа).

6. UI-КОМПОНЕНТЫ (src/components/ui), каждый строго по DESIGN.md, раздел 6
- Icon (весь набор из раздела 5, встроенный SVG), Button (primary,
  secondary, text), IconButton, AddButton, Pill, Chip, SegmentedControl,
  Input, Stepper, Card, HeroCard, GoalCard, StitchBar, StitchRing,
  StatTile, Cover (CSS-обложка по хэшу названия и вариант с картинкой).
- Остальные компоненты из раздела 6 (WeekBars, Heatmap, YearSpines,
  NoteCard, BookRow, HistoryList) пока не делай: они появятся в своих
  фазах.

7. ЭКРАНЫ
- Заглушки: / (Главная), /library (Книги), /session (Сессия), /notes
  (Заметки), /stats (Статистика): PageHeader, заголовок и пустой блок
  «Скоро». Тексты из словарей.
- /settings: переключатели языка (RU/EN) и темы (светлая/тёмная), рабочие.
  Открывается иконкой настроек в шапке главной.
- /dev/kit (только в development): страница-витрина, где все UI-компоненты
  видны в обоих темах рядом (с переключателем темы), для проверки
  владельцем.

8. ГОТОВО, КОГДА
- npm run dev запускается без ошибок; lint, typecheck и build проходят.
- В мобильном viewport 390 px главная и все заглушки выглядят как макет:
  нижняя навигация, кнопка «Старт», фон, шрифты.
- Тема и язык переключаются и сохраняются после перезагрузки.
- Приложение ставится на домашний экран Android Chrome и открывается без
  адресной строки (проверит владелец по https-ссылке Vercel; деплой
  настраивает владелец, ты его не трогаешь).
- В компонентах нет hex-значений и «зашитых» строк интерфейса.
- Все интерактивные элементы не меньше 44×44, у иконок есть aria-label.

ПРАВИЛА
- Git не трогай: никаких commit, push, branch, reset. В конце скажи, что
  изменено.
- Если в DESIGN.md чего-то не хватает, не придумывай: выбери самое простое
  решение по токенам и укажи это в отчёте.
- Ничего из Supabase, Google Books, таймера и реальных данных не делай, это
  следующие фазы.

ОТЧЁТ В КОНЦЕ: что сделано, список созданных файлов, как запустить, как
проверить на телефоне, что отклонилось от DESIGN.md и почему, какие
зависимости добавлены.
```

## Фаза 1.5 — Вид для ПК

Ветка: `phase-1-5/desktop-shell`. Перед проверкой превью на Vercel владелец отключает Deployment Protection (иначе превью ветки закрыто входом).

```
Прочитай по порядку: docs/STATE.md (жёсткие правила), docs/PLAN.md
(Фаза 1.5) и docs/DESIGN.md, особенно раздел 7.1 «Компьютер».
Композицию сверяй с docs/mockups/desktop-home.png,
desktop-library.png, desktop-stats.png. В начале ответа предложи имя
ветки по правилу из STATE.md (подойдёт phase-1-5/desktop-shell) и
продолжай: ветку создаст владелец.

ЗАДАЧА: Фаза 1.5 — оболочка для ПК. Сейчас на компьютере приложение
показано узкой колонкой 480 px по центру. Нужно: от 1024 px включается
боковая панель и широкий контент, телефонный вид не меняется. Данных
по-прежнему нет, экраны остаются заглушками.

1. ПЕРЕКЛЮЧЕНИЕ ВИДА
- Брейкпоинт 1024 px (в Tailwind lg заменить на 1024 или завести
  отдельный). Меньше: всё как сейчас (BottomNav, колонка).
  Больше: боковая панель, BottomNav скрыта.
- Только CSS (классы по брейкпоинту), без определения устройства в JS и
  без мигания при загрузке.

2. БОКОВАЯ ПАНЕЛЬ (src/components/layout/Sidebar)
- Строго по DESIGN.md, раздел 7.1: ширина 248, фон --nav,
  border-right 2px dashed --stitch; логотип, кнопка «Начать сессию»,
  навигация (Главная, Книги, Заметки, Статистика), снизу мини-карточка
  «Сегодня» и кнопка «Настройки».
- Мини-карточка «Сегодня» пока показывает заглушку (0 из 30), данные
  придут в Фазе 4.
- Навигация использует те же маршруты и ту же логику активного пункта,
  что BottomNav. Общий список пунктов вынеси в одно место, чтобы не
  дублировать.
- «Начать сессию» ведёт на /session, как «Старт» на телефоне.

3. AppShell
- От 1024 px: сетка «панель 248 + контент». Контент: отступы 32 40 40,
  контейнер max-width 1200 по центру. Колонку 480 на ПК убрать.
- Меньше 1024 px: без изменений.
- /session и /session/finish (если есть): на ПК без боковой панели,
  колонка до 480 по центру (раздел 7.1).
- /settings, /notes и прочие заглушки: контент до 720 по центру.

4. PageHeader
- На ПК заголовок 34, действия справа. Остальное по DESIGN.md.

5. ЗАГЛУШКИ ГЛАВНОЙ, КНИГ, СТАТИСТИКИ
- Главную, /library и /stats на ПК пока оставь заглушками «Скоро», но
  внутри контента: чтобы виден был правильный каркас. Сами блоки макетов

6. КЛАВИАТУРА И МЫШЬ
- Видимый фокус: outline 2px solid var(--accent), offset 2, на всех
  интерактивных элементах (глобально, через :focus-visible).
- Ховер: фон пункта навигации и строк светлеет на ступень
  (--surface-2), cursor: pointer.

7. ВИТРИНА /dev/kit
- Добавь Sidebar в витрину. Ширину страницы витрины на ПК не ограничивай
  колонкой 480.

8. ГОТОВО, КОГДА
- На 1440 px: слева панель 248, справа контент до 1200, BottomNav нет,
  кнопка «Начать сессию» вверху панели, активный пункт подсвечен.
- На 1024 px всё помещается без горизонтального скролла.
- На 390 px и 360 px вид полностью как до фазы (BottomNav, колонка).
- Тема и язык по-прежнему переключаются и сохраняются.
- Проходят lint, typecheck, build.
- В компонентах нет hex-значений и «зашитых» строк. Зоны ≥ 44×44, у

ПРАВИЛА

- Если чего-то не хватает в DESIGN.md, выбери простое решение по
  токенам и укажи в отчёте.
- Не делай блоки главной, библиотеки и статистики, данные и базу: это
  следующие фазы.
- Service worker не меняй (если увидишь проблему, только опиши в

ОТЧЁТ В КОНЦЕ: что сделано, список файлов, как проверить на ПК и на
```
