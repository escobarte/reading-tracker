# Ключ Google Books API: получение и подключение

Для чего: поиск книг по названию и автору в Фазе 3 (обложка, страницы, язык). Ключ бесплатный. Без ключа поиск тоже работает, но с маленьким общим лимитом, поэтому ключ нужен.

Правило: ключ лежит только в переменных окружения на сервере. В git, в клиентский код и в чаты его не вставляем. Имя переменной **без** `NEXT_PUBLIC_`, иначе Next.js отдаст её в браузер.

## 1. Google Cloud: проект

1. Открой https://console.cloud.google.com и войди в Google-аккаунт. Если появится окно с условиями, поставь галочку и нажми «Agree and continue».
2. Вверху слева, рядом с логотипом, нажми на название проекта (или «Select a project»).
3. В окне справа вверху нажми **New project**.
4. Project name: `Reading Tracker`. Location не меняй.
5. Нажми **Create**. Через несколько секунд проект создастся, его название появится вверху.

### Если консоль пишет «Blocked» и требует двухэтапную аутентификацию (2-Step Verification)

Google Cloud не работает на аккаунте без неё.
1. Открой https://myaccount.google.com/signinoptions/twosv
2. Нажми «Включить двухэтапную аутентификацию» и пройди подсказки (удобно через приложение Google Authenticator).
3. Вернись в консоль и обнови страницу (F5). Если блок остался, подожди пару минут и обнови снова.

## 2. Включить Books API

1. Левое меню → **APIs and services** → **Library**.
2. В поиске напиши `Books API`, нажми Enter.
3. Открой карточку **Books API** и нажми **Enable**.
4. Открылась страница «API/Service details», Status: **Enabled**. Значит, готово.

## 3. Создать ключ

1. На странице Books API нажми **Create credentials** (справа вверху).
2. «Select an API»: **Books API**.
3. «What data will you be accessing?»: **Public data** (не «User data» и не «Application data»).
4. Нажми **Next**. Появится окно «API key created» с ключом, он начинается с `AIza`.

Если окно закрылось: левое меню → **Credentials** → в таблице «API keys» строка «API key 1» → **Show key**.

## 4. Ограничить ключ

Ограничение защищает ключ: даже если он утечёт, им нельзя пользоваться ни для чего, кроме Books API.

1. **Credentials** → нажми на название ключа («API key 1»). Или в окне создания нажми **Restrict key**.
2. Блок **API restrictions** → выбери **Restrict key**.
3. Список «Select APIs» → отметь **Books API** → **OK**.
4. Блок **Application restrictions** оставь **None**. Vercel не даёт постоянный адрес сервера, поэтому ограничение по сайту или IP не подойдёт.
5. Внизу нажми **Save**.
6. Если после Save тебя вернуло на страницу мастера «Credential Type», нажми **Cancel** и открой **Credentials**. В таблице у ключа в колонке Restrictions должно быть **Books API**.

Изменения вступают в силу до пяти минут.

Предупреждение «Remember to configure the OAuth consent screen» игнорируй: OAuth нам не нужен.

## 5. Добавить ключ в Vercel

1. Скопируй ключ: Credentials → **Show key** → иконка копирования. Копируй только сам ключ (всё поле «Your API key»), а не фразу `key=API_KEY` из подсказки.
2. Vercel → проект Reading Tracker → **Settings** → **Environment Variables** → **Create new** (или «Add Another»).
3. Заполни:
   - **Type**: Secret (значение скроется, после сохранения его уже не показать)
   - **Key**: `GOOGLE_BOOKS_API_KEY`
   - **Value**: только ключ, без кавычек, пробелов и без `GOOGLE_BOOKS_API_KEY=`
   - **Environments**: Production и Preview
4. Сохрани. В списке появятся две строки (Preview и Production) со значком замка: Vercel для Secret показывает их отдельно, это нормально.
5. Переменные подхватываются **новым** деплоем. После добавления ключа запусти редеплой (Deployments → три точки у нужного деплоя → Redeploy) или просто запушь новый коммит.

## 6. Ключ для запуска на своём компьютере (необязательно)

Нужно, только если запускаешь `npm run dev` локально. Если проверяешь на превью Vercel, пропусти.

1. Открой файл `.env.local` в корне проекта (он в `.gitignore`, в git не попадает).
2. Добавь строку:
   ```
   GOOGLE_BOOKS_API_KEY=твой_ключ
   ```
3. Останови `npm run dev` (Ctrl+C) и запусти заново: переменные читаются при старте.
4. В `.env.example` добавь строку без значения: `GOOGLE_BOOKS_API_KEY=`

## 7. Проверка

1. Открой превью или сайт, зайди в **Книги** → **+** и введи в поиск, например, `Мастер и Маргарита` или `Dune`. Должны появиться результаты с обложками.
2. Ключ не должен быть виден в браузере: в DevTools (F12) → Network браузер обращается только к `/api/books/search?...` на твоём сайте, а запросов напрямую к `googleapis.com` нет.
3. Быстрая проверка самого ключа (подставь ключ вместо `KEY`, ссылку никому не отправляй):
   `https://www.googleapis.com/books/v1/volumes?q=intitle:dune&key=KEY`
   Если в ответе список `items`, ключ работает.

## 8. Если что-то не работает

| Что видишь | Причина и что делать |
|---|---|
| Консоль Google пишет «Blocked» | Нужна двухэтапная аутентификация, раздел 1 |
| В ответе `403`, «API has not been used in project … or it is disabled» | Books API не включён в этом проекте: раздел 2 |
| В ответе `403`, «API key not valid» или «API_KEY_SERVICE_BLOCKED» | Ключ вставлен с ошибкой (лишние символы или пробелы) или в ограничениях выбран не Books API. Проверь раздел 4 и значение в Vercel |
| Сразу после Save ограничений ошибка | Подожди до 5 минут |
| На сайте поиск не находит ничего, а локально работает | В Vercel нет переменной для нужного окружения (Production или Preview) или не было редеплоя после добавления |
| `429`, «Quota exceeded» | Исчерпан дневной лимит. Бесплатный лимит у Books API большой (порядка 1000 запросов в день на проект по умолчанию), для личного приложения его хватает. Запасной поиск через Open Library сработает автоматически |

## 9. Если ключ попал куда не надо

(в чат, в git, на скриншот с открытым значением)

1. Google Cloud → Credentials → нажми на ключ → **Rotate key** (или создай новый ключ по разделам 3–4 и удали старый кнопкой **Delete**).
2. В Vercel обнови значение `GOOGLE_BOOKS_API_KEY` (и Production, и Preview) и сделай редеплой.
3. Обнови `.env.local`.
4. Если ключ попал в git, достаточно заменить ключ: после ротации старый ключ перестаёт работать.
